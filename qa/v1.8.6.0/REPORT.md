## 4. 복합장갑

외측→내측의 두께 비율과 구성 밀도:

- Ceramic: 50% × 3200 + 30% × 7850 + 20% × 1725 = **4300kg/m³**.
- Tungsten: 50% × 18000 + 25% × 4500 + 25% × 1500 = **10500kg/m³**.
- Nano: 40% × 7000 + 35% × 5000 + 25% × 2600 = **5200kg/m³**.

300mm 장갑의 각 층 두께 합계는 300mm다. 모든 층은 ID/순서/구성 재료/두께/밀도/물리 역할/미래 실패 모델 ID와 실제 체적·질량을 가진다. 곡면과 모서리에서는 층마다 면적·체적이 달라질 수 있으므로, 두께가중 기준 밀도와 실제 체적가중 평균 밀도(`mass / volume`)를 둘 다 공개한다. 질량에는 각 구성층의 선언된 밀도만 사용한다.

## 5. 두께·재질·공통 정책

기존 `firepower/survivability/mobility/endurance/missile/sensor`를 보존하고 ARMOR→survivability, MISSILES→missile, SENSORS→sensor로 연결한다. Hull 두께는 길이와 함종 보호 교리, 기동/항속 정책으로 결정한다(8–42mm 범위). Armor는 기존 부위/중요도/함종/길이에 따른 목표를 먼저 정한 뒤 실제 노출 면적·밀도 상한과 유한 장갑 예산으로 조정한다. 최소 외피와 실제 존재하는 장비, 추정 구조/지원 및 최소 장갑층 예산을 먼저 확보한다.

같은 목표 질량의 잔여 자원을 구조/장갑/추진/항속/센서/장비 사이에 정규화 배분한다. 모든 우선순위가 100이어도 총 배분량은 목표를 넘지 않는다. 부족한 필수 최소량은 `REQUIRED_PHYSICAL_MASS_BUDGET_EXCEEDED`로 거절한다. 실제 질량을 목표값으로 덮어쓰지 않는다.

미래 골조 밀도·중복성, 격벽 분할/보호, 보호 체적, 계통 분산, 추진 지지, 사격통제/미사일/센서 지원 방호는 `POLICY_ONLY_NOT_GENERATED`다. 내부 설비를 이미 설치한 것으로 보고하지 않는다.

## 7. 피복률과 포화

8개 설계 모두 기존 판 경계를 보존한다. Hull 노출면 중심과 3개 안쪽 꼭짓점 방향의 면적가중 샘플 **688개**에서 Armor 선행 피복률은 약 **99.554%**로 동일했다. 이는 실제 요청한 Ray 기반의 제한적 근사이며 함선 전체의 정확한 피복률이 아니다. 우선순위로 개구부/기존 빈 영역에 새 판을 만들지 않았기 때문에 범위 증가는 포화로 기록된다. 차이가 없는 결과를 성공적인 피복률 증가로 주장하지 않는다.

원본 렌더 장갑의 모든 면적(묻힌 면 포함)과 살아남은 외측 물리 면적의 비율은 별도 `sourceAreaRetention`이다. 방향별 결과·표본 수·중요 구역 면적은 `controls/comparison.json`에 보존했다. 면적 유지율을 전방위 방호율로 표시하지 않는다.

## 10. 물리 Geometry / Ray Probe

렌더링 원본의 실제 삼각형/판 ID를 사용한 **유한 정상 방향 표면층**이다. 부착면·묻힌 면·이미 등록된 물질과의 중첩을 잘라 제거한다. 빈 곳에 무한 평판을 생성하지 않는다. 외측 좌표를 유지하고 내측으로 깊이를 구성한다. 각 코팅 셀과 층의 깊이 경계만 저장하고 필요할 때 층별 체적을 복원하므로 Geometry를 층마다 중복 저장하지 않는다.

Probe는 실제 Entry/Exit, plate/shell/material/구성층, 정상 깊이/실제 위치의 정상 두께, 통과 길이, 입사각, 표면/경계 법선, 피복 여부, 근사 경고를 반환한다. 장갑이 없으면 Hull부터 시작한다. 0°/30°/60° 평판 경로는 300 / 346.410 / 600mm와 일치했다. 가장자리 이탈은 무한 평판 식보다 짧아지고, 스침각은 유한 거리로 제한되며 잘못된 Ray는 거절한다. Quaternion 회전/이동, 비평행 후면, 경사진 면 및 면 법선이 다른 곡면 근사 검사도 통과했다. 실제 관통 에너지는 계산하지 않는다.

## 12. Blueprint / Seed / Free-Mount

schemaVersion 2의 선택적 확장과 별도 물리/Registry 버전을 사용한다. 구버전은 자동 재작성하지 않고 그대로 로드한다. schema1 저장본은 필요한 StructuralVolume 물리 계약이 없어 기존 렌더링 전용으로 유지한다. schema2의 명시적 마이그레이션만 기본/추정 출처 `MIGRATED_DEFAULT_ESTIMATE`를 표시하며 Hull/Armor/무장/플랫폼을 보존한다. 고정 설계와 개별 손상 상태 계약을 분리했고 같은 Blueprint의 인스턴스는 독립 상태를 가진다.

대표 Seed 7/11/23의 전체 생성→반복 JSON 일치가 통과했다. Production의 실제 Export/Import/Reload와 과거 저장본/명시적 migration 검사를 수행했다. Free-Mount는 외부 접촉/간섭 검사만 유지하며 내부 공간·급탄·배전·실하중·질량 예산을 새 설치 조건으로 추가하지 않았다. 질량 초과 플레이어 로드아웃은 표시만 한다. 장비/플랫폼 중복 질량 및 Undo의 원본 JSON 복원도 확인했다.

## 13. 성능 — 목표 미달

| 함선      | 현 코드 5.5 ms | 6.0 최초 ms | 6.0 동일 입력 반복 ms | 반복 JSON 일치 | 셀 수 |
| --------- | -------------- | ----------- | --------------------- | -------------- | ----- |
| aegis470  | 3656           | 10184       | 3525                  | True           | 12380 |
| vesper200 | 4646           | 19158       | 6726                  | True           | 31330 |
| forge300  | 8028           | 25645       | 10818                 | True           | 35540 |

성능은 다른 브라우저 QA와 병행하지 않고 같은 현 코드에서 구버전 경로와 새 경로를 순차 측정했다. 기능 확인용 통제 비교의 planningMs는 성능 비교에 사용하지 않았다. 중앙값은 **4,646 → 19,158ms (+312.3%)**, 동일 입력 반복은 **6,726ms**다. 과거 보고 4,410ms를 현재 기준인 것처럼 사용하지 않았다. 표본은 대표 3척이며 광범위 통계가 아니다.

**최초 생성 성능 목표는 충족하지 못했다.** 유한 층 분할/중첩 제거와 재검증, 큰 JSON 직렬화가 비용이다. 소스 캐시 4개와 최근 물리 결과 1개 및 입력 내용 전체를 검증하는 성공 판정 1개의 제한된 캐시, 층 Geometry 파생 저장, 요청 시 Probe 캐시, 단일 Debug draw call, 외부 장착 Worker에서 물리 데이터 생략을 적용했으나 냉간 비용을 충분히 줄이지 못했다. UI의 숨은 pretty JSON도 큰 메모리/직렬화 비용으로 남는다. 캐시 반복 수치로 최초 비용을 숨기지 않는다.

## 15. 실패 실험과 남은 한계

- 초기 방사형 inset은 내부 kernel까지의 짧은 거리에 좌우되어 극미소 두께가 생겼다. 해당 방식은 폐기하고 유한 정상 방향 층으로 바꿨다. 초기 자료는 `experiments/`에 별도 보존했다.
- 기존 비볼록 외장 Solid 일부는 닫힌 볼록/별형 몸체로 인증할 수 없었다. 실패한 몸체를 정상 덩어리 장갑으로 등록하지 않고, 검증 가능한 유한 면층만 별도 근사 경고와 함께 등록한다. 전체 비볼록 내부의 정확한 정상 offset은 구현하지 않았다.
- 층별 Geometry 중복은 셀 수/JSON 비용을 키웠다. 코팅 셀+층 경계 저장으로 바꿨다. 복잡한 함선의 큰 데이터와 생성 비용은 여전히 남는다.
- 최초 예산 배분은 최소 장갑보다 선택 예약을 앞세워 일부 주문을 거절했다. 최소 유효 장갑 예산을 먼저 확보하도록 수정했다. 질량을 목표로 덮어쓰지 않았다.
- 일부 거의 공선인 클립 꼭짓점이 불안정한 삼각형 법선을 만들었다. 원본 좌표 기반의 제한된 재삼각화 후보를 검증한다. 기존 10µm 기하 판정은 유지하고 원래 꼭짓점도 그 허용 오차 내에 포함되는지 확인한다. 해석에 실패하면 여전히 명시적으로 거절한다. 재현 셀을 회귀 Fixture로 보존했다.
- 원본 면의 가까운 분할 경계 면적을 단순 합산하면 중복 면적이 생겼다. 실제 외측 폴리곤 합집합으로 수정했고 면적 수치를 강제로 clamp하지 않았다.
- 최종 시각 확인에서 정확히 셀 경계를 따라가는 Ray의 Hull 누락을 발견했다. 외부 장착용 인덱스의 엄격한 AABB 교차 조건이 원인이었다. Probe 검색 상자만 1e-7m 확장하고 실제 유한 셀 교차 검사는 유지하여 해결했다. 실물 두께/Geometry/장착 규칙은 바꾸지 않았다. 경계 회귀와 실제 Hull Ray를 재확인했다.
- 최종 보완 QA에서 병행 브라우저의 30초 navigation 상한을 초과했다. 큰 Blueprint 객체 전달도 오래 걸려 중단 후 JSON 문자열 전달/자료 조회 전용 페이지로 재실행했다. 여덟 설계의 기능 비교와 세 Probe 재조회는 각각 완료했으며 최종 Production 재실행은 120초 로드 허용으로 기능 판정 20개를 그대로 통과했다. 실패 로그를 보존하고 전송/병행 실행 시간은 성능 비교에서 제외했다.
- 개발 중 브라우저 시간 초과와 잘못된 기본 QA 포트 연결도 있었다. 최종 관련 QA는 완료된 결과만 사용했다.
- 곡면은 기존 faceted 메시 근사이고 모서리에서는 층이 가늘어진다. 1e-7m 공선 정리, 최대 1e-7m hull 후보 구성 정밀도, 1e-5m plane 판정, Renderer Float32 오차가 있다. 저장 셀에 대한 Entry/Exit는 직접 계산하지만 매끈한 연속체의 완전한 정확도로 주장하지 않는다.
- 회전/이동 Quaternion은 지원하지만 비균일 스케일 및 회전된 개별 StructuralVolume은 이 계약 밖이다.
- 기존 SPINE형 Volume은 Hull 외피 등록에서 제외하고 구조 질량 추정에 남긴다. 해당 부재의 정확한 물리 재료/방호층은 V1.8.6.1 골조 계약에서 연결해야 한다. 본 버전의 Probe가 모든 보이는 구조 부재를 물리화했다고 주장하지 않는다.
- 계산 보호 상한은 노출면 128 폴리곤, 국소 분할 256개, 전체 코팅 셀 40,000개다. 초과 시 계산 복잡도 사유로 명시적으로 거절하며 이를 실제 재료공학적 불가능과 혼동하지 않는다.
- 실제 골조/추진/기능 장비 질량, 탄종별 재질 파괴/관통 계수, 정확한 전방위 피복 적분과 대규모 Seed 경향은 미검증이다. 현재 예산/성능 예약을 완성된 전투 능력으로 해석하면 안 된다.
